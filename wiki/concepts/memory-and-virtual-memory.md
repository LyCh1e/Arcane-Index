# Memory Management and Virtual Memory

Covers address binding, the MMU, paging, TLB, page table structures, virtual memory, demand paging, page replacement algorithms, thrashing, and the working-set model.

---

## 1. Background

- CPU can access only **registers** and **main memory** directly
- A programme must be loaded into memory before execution
- **Cache** sits between CPU registers and main memory to bridge the speed gap
- Memory protection required: the OS prevents user programmes from accessing kernel memory or each other's memory

### Base and Limit Registers

Each process is given a pair of hardware registers:
- **Base register**: smallest physical address the process may access
- **Limit register**: size of the legal address range

Every memory access is checked: `base ≤ address < base + limit`, otherwise trap to kernel.

---

## 2. Address Binding

Addresses in a programme go through several transformations before execution:

| Stage | Address form | When binding occurs |
|-------|-------------|-------------------|
| **Source code** | Symbolic (`count`, `loop`) | — |
| **Compile time** | Relocatable (14 bytes from module start) | Fixed → absolute if start address known at compile time |
| **Link/load time** | Absolute | If start address known only at load time |
| **Execution time** | Virtual (logical) | If process can be moved during execution |

### Logical vs Physical Address

- **Logical (virtual) address**: generated by the CPU
- **Physical address**: seen by the memory unit (actual DRAM location)
- Identical at compile/load time; differ at execution time

---

## 3. Memory Management Unit (MMU)

Hardware device that translates **logical → physical** address at runtime.

**Simple scheme (relocation register)**: physical = logical + relocation_register. The user programme only sees logical addresses.

**Dynamic loading**: routines loaded only when called — unused code never loaded. Better space utilisation. No OS support required (implemented in programme).

**Dynamic linking**: linking deferred to execution. A stub locates the library routine in memory (or loads it). Shared libraries can be patched without recompiling applications.

---

## 4. Contiguous Memory Allocation

Memory divided into: OS region (low) + user processes region (high).

**Variable partition**: each process gets exactly the memory it needs.

**Placement policies**:
| Policy | Description |
|--------|-------------|
| **First-fit** | Allocate first hole ≥ request size; fast |
| **Best-fit** | Smallest hole ≥ request size; minimises leftover, but slow |
| **Worst-fit** | Largest hole; leaves biggest leftover; worst in practice |

First-fit and best-fit outperform worst-fit.

**50% rule**: first-fit analysis shows ~0.5N blocks wasted for N allocated.

---

## 5. Fragmentation

| Type | Cause | Solution |
|------|-------|---------|
| **External** | Enough total free memory, but not contiguous | Compaction (shuffle processes) — only possible with execution-time binding |
| **Internal** | Allocated partition larger than requested | Smaller partition sizes |

---

## 6. Paging

Paging **eliminates external fragmentation** by allowing non-contiguous allocation.

| Term | Definition |
|------|-----------|
| **Frame** | Fixed-size chunk of physical memory (power of 2, typically 4 KB) |
| **Page** | Fixed-size chunk of process logical memory (same size as frame) |
| **Page table** | Per-process mapping: page number → frame number |

A process of N pages needs N free frames (not necessarily contiguous).

### Address Translation

```
Logical address = [ page number (p) | page offset (d) ]
                         ↓ index into page table
                    frame number (f)
                         ↓
Physical address = [ frame number (f) | page offset (d) ]
```

For logical address space 2^m and page size 2^n: p uses (m−n) bits, d uses n bits.

**Paging still has internal fragmentation** — the last page of a process is typically partially used. Average waste: ½ page per process.

### Page Table Implementation

| Method | Speed | Cost | Notes |
|--------|-------|------|-------|
| Hardware registers | Very fast | Expensive; only for small tables | Context switch overhead |
| Main memory (PTBR) | Slower | Cheap | Every access requires 2 memory reads (table + data) |
| **TLB** | Fast | Moderate | Caches recent page→frame translations |

**PTBR** = Page Table Base Register; **PTLR** = Page Table Length Register.

### TLB — Translation Look-aside Buffer

A small, fast associative hardware cache of (page number → frame number) entries.

```
CPU generates logical address
         ↓
   TLB lookup (parallel search)
   ↙             ↘
TLB hit           TLB miss
  ↓                  ↓
frame found      look up page table in memory
  ↓                  ↓
                 add entry to TLB
         ↓
form physical address and access memory
```

**Effective Access Time (EAT)**:
```
EAT = hit_ratio × memory_access + (1 − hit_ratio) × 2 × memory_access

Example (99% hit ratio, 10 ns access):
EAT = 0.99 × 10 + 0.01 × 20 = 10.1 ns  (only 1% slowdown)
```

TLBs store **ASIDs** (Address Space IDs) to allow multiple processes' entries to coexist without flushing on every context switch.

### Memory Protection via Page Table

- **Valid–invalid bit**: marks whether a page is in the process's legal address space
- **Protection bits**: read-only, read-write, execute permissions per page

### Shared Pages

Read-only code (e.g., standard library, compiler) can be shared: multiple processes map to the same physical frames. Each process keeps private data pages.

---

## 7. Page Table Structures

A 32-bit address space with 4 KB pages → 1 million page table entries → 4 MB of page table per process. Solutions:

### Hierarchical Paging (Two-Level)

Page the page table itself. A 32-bit logical address: 10-bit outer page, 10-bit inner page, 12-bit offset.

```
logical address: [ p1 (10) | p2 (10) | d (12) ]
    p1 → outer page table → inner page table
    p2 → inner page table → frame number
    frame + d → physical address
```

64-bit spaces require 3+ levels.

### Hashed Page Tables

Virtual page number is hashed. Each bucket is a linked list of (VPN, frame, next) entries — handles collisions. Used for >32-bit address spaces.

**Clustered page tables**: each entry covers 16+ pages — useful for sparse address spaces.

### Inverted Page Table

**One global table** for the entire system, indexed by physical frame number. Each entry: (VPN, process ID). 
- Advantage: small, fixed size
- Disadvantage: slow search (must scan by VPN); usually combined with hash

---

## 8. Swapping

A process can be temporarily **swapped out** to a backing store (disk) and later swapped back in.

- Increases degree of multiprogramming
- Main cost is **transfer time** (proportional to amount of memory swapped)
- Modern OS uses swapping with paging: swap individual pages, not whole processes

---

## 9. Virtual Memory

Virtual memory separates **user logical memory** from **physical memory**. Only the part of a programme actually needed need be in memory at any time.

Benefits:
- Logical address space can be **much larger** than physical memory
- Multiple processes share physical memory more efficiently
- Processes start faster (less initial loading)

### Virtual Address Space

```
High address (max logical)
  Stack ↓   (grows down)
  [hole]    (no physical memory allocated unless needed)
  Heap  ↑   (grows up)
  Data / BSS
  Text
Low address (0)
```

---

## 10. Demand Paging

Pages are loaded into memory **only when accessed** (lazy loading). A **pager** (not a swapper) manages individual pages.

### Valid–Invalid Bit

Each page table entry has a valid/invalid bit:
- **v**: page is in memory
- **i**: page is on disk (or not in process's address space)

Accessing an invalid page → **page fault** (trap to OS).

### Page Fault Handling (6 Steps)

1. Reference causes trap to OS (page fault)
2. OS checks internal table: invalid reference → terminate; valid but not in memory → proceed
3. Find a free frame
4. Schedule disk read of the page into the free frame
5. Update page table (set valid bit = v)
6. Restart the interrupted instruction

### EAT with Page Faults

```
EAT = (1 − p) × memory_access + p × (fault_overhead + swap_out + swap_in)

Example: memory_access = 200 ns, fault service = 8 ms
EAT = 200 + p × 7,999,800

For < 10% degradation: p < 1 in 400,000 accesses
```

## 11. Page Replacement Algorithms

When no free frames exist, a **victim page** must be evicted.

**Dirty bit**: if a page has been modified in memory, it must be written to disk before eviction. Clean pages can be evicted for free.

### FIFO — First-In-First-Out

Evict the oldest page. Simple (FIFO queue). Suffers from **Belady's anomaly**: more frames can cause more page faults.

### Optimal (OPT)

Evict the page that will not be used for the longest time. Optimal (minimum page faults) but requires knowledge of the future — used only as a benchmark.

### LRU — Least Recently Used

Evict page with oldest last-use timestamp. Good in practice; approximates OPT. No Belady's anomaly.

**Implementation**: counter (copy clock on each access) or doubly-linked list. Needs hardware support.

### LRU Approximations

**Reference bit**: set to 1 on access; OS periodically clears bits. Replace any page with ref bit = 0.

**Second-chance (clock) algorithm**:
- Circular queue of pages
- On eviction candidate: if ref bit = 1, clear bit and skip; if ref bit = 0, evict

**Enhanced second-chance** — use (reference, modify) pairs:
| Pair | Meaning | Replace priority |
|------|---------|-----------------|
| (0, 0) | Not used, not modified | Best — replace first |
| (0, 1) | Not used, modified | Must write back first |
| (1, 0) | Used, clean | Likely to be used again |
| (1, 1) | Used, modified | Worst — used and dirty |

### Counting Algorithms

- **LFU** (Least Frequently Used): replace page with smallest reference count
- **MFU** (Most Frequently Used): replace most referenced (newly loaded pages have small counts)

## 12. Frame Allocation

**Minimum frames**: each process needs a minimum number of frames to execute even one instruction without a page fault.

**Allocation strategies**:
- **Equal allocation**: N frames / n processes each
- **Proportional allocation**: frames ∝ process size

**Global replacement**: any frame can be stolen from any process — higher throughput but variable per-process performance.

**Local replacement**: each process selects only from its own frames — consistent performance but possible memory underutilisation.

**Reapers**: kernel routines triggered when free-frame list falls below a threshold.

---

## 13. Thrashing

A process is **thrashing** when it spends more time paging than executing.

**Cause**: process does not have enough frames; it continuously page-faults and each replacement evicts a page that will be needed immediately.

**Why demand paging works**: locality model — a programme migrates between localities; each locality fits in a modest number of frames.

**Thrashing occurs when**: total size of all localities > total physical memory.

### Working-Set Model

**Working set** WSSᵢ(Δ) = set of pages referenced in the last Δ memory references.

- Δ too small → misses pages in current locality
- Δ too large → includes pages from multiple localities
- D = Σ WSSᵢ ≈ total frames needed

**Policy**: if D > total frames → suspend a process until D ≤ total frames.

### Page-Fault Frequency (PFF)

More direct control:
- PFF too low → process has too many frames; take some away
- PFF too high → process needs more frames

---

## 14. Other Considerations

- **Prepaging**: load pages expected to be needed before first reference — reduces startup page faults
- **TLB reach**: (TLB entries) × (page size) — ideally the working set fits in TLB
- **I/O interlock (page pinning)**: pages involved in I/O must not be evicted — locked in memory during transfer
- **Programme structure**: row-major vs column-major traversal of a 2D array can differ by orders of magnitude in page faults
