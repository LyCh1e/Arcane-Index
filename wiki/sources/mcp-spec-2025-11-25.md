# MCP 2025-11-25 Specification Release

## Summary

The first major specification update to MCP, published exactly one year after launch. This release expanded MCP from a synchronous tool-calling protocol into an architecture capable of supporting secure, long-running, governed workflows in production environments.

## Key Features

### Async Tasks Primitive (SEP-1686)
Any request can now return a task handle instead of blocking. The client polls or subscribes to status transitions:
- `working` → `input_required` → `completed`
- `working` → `failed`
- `working` → `cancelled`

This enables healthcare analytics pipelines, enterprise automation, and multi-agent orchestration — use cases where a tool might take minutes rather than milliseconds.

### Client ID Metadata Documents (CIMD)
Replaces Dynamic Client Registration (which required a round-trip registration call to every server). Clients self-host a metadata URL as their identity, anchored in DNS and HTTPS. The result is a decoupled trust model: server operators can verify client identity without a prior relationship.

### Machine-to-Machine OAuth (`client_credentials`)
Headless agents and background automation scripts no longer require a user consent flow. Supports fully automated agent pipelines.

### Cross App Access (XAA)
Enterprise identity providers regain visibility and control when users connect MCP clients to downstream tools. Enables centralised policy enforcement at the IdP level.

### Extensions Framework
A formal, composable extension system. Optional capabilities can be negotiated between client and server without modifying the core spec. Prevents protocol bloat while allowing ecosystem innovation.

### Developer Experience Fixes
- Standardised tool-name formatting
- Clearer RPC payload definitions
- Improved SSE disconnect handling
- Better SDK version negotiation rules

## Backward Compatibility

Fully backward-compatible with existing implementations. Existing servers and clients continue to function without modification; new features are opt-in via capability negotiation.
