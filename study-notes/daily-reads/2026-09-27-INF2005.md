## Diffie–Hellman Key Exchange

DH lets two people agree on a secret key over a public channel — without ever sending the key itself. It's **not** encryption, just key agreement.

How it works:
1. Alice and Bob publicly agree on a prime `p` and a generator `G`.
2. Each picks a private secret (`a`, `b`) — never shared.
3. They exchange public values: `A = Gᵃ mod p`, `B = Gᵇ mod p`.
4. Alice computes `K = Bᵃ mod p`; Bob computes `K = Aᵇ mod p`. Both land on the same `K = G^(ab) mod p`.

An eavesdropper sees `p`, `G`, `A`, `B` — but can't work out `K` without solving the discrete logarithm problem (very hard for large primes).

> [!warning] Watch out
> DH ≠ RSA. RSA's security rests on the **factoring problem**. DH's security rests on the **discrete logarithm problem**.

## Authentication Factors

Access control flow: Identification (who are you?) → Authentication (prove it) → Authorisation (what can you do?).

Three factors — remember **KTB**:
- **Knowledge** — something you know (password, PIN)
- **Token** — something you have (smart card, RFID)
- **Biometric** — something you are (next section)

MFA combines two or more factors — much stronger than any one alone.

Password storage, weakest to strongest: Plaintext → Encrypted → Hash → **Hash + salt** (best — a unique salt per user defeats rainbow tables).

Common attacks: brute force, dictionary attacks, rainbow tables (beaten by salting), social engineering, and Google dorking (searching for leaked files, e.g. `ext:csv inurl:passwd`).

RFID tokens can be spoofed over the air, sniffed via MITM, or read via power side-channel analysis.

> [!warning] Watch out
> Knowing which bucket (Knowledge / Token / Biometric) a mechanism belongs to is a common one-mark question.

## Biometric Authentication

A good biometric needs **UDPC**:
- **Universality** — everyone has it
- **Distinctiveness** — differs enough between people
- **Permanence** — stays stable over time
- **Collectability** — can actually be measured

Two accuracy metrics:
- **FAR** (False Accept Rate) — wrongly lets an impostor in
- **TAR** (True Accept Rate) — correctly lets the real user in

Loosen the match threshold → both FAR and TAR rise together (the ROC curve plots this trade-off).

Modality comparison: retina (most accurate, most invasive) → iris → fingerprint (cheap, fast) → face (fast, ML-boosted, but spoofable) → gait/keystroke (continuous, behavioural).

> [!warning] Watch out
> Facial recognition has a real bias problem — false-positive rates can be up to 100× higher for Asian and Black individuals than for white individuals.
